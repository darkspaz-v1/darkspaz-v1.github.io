ShortsForge

One command turns a topic into a finished video.

Type a topic. It writes the script, plans the scenes, writes the image prompts, speaks the narration, and cuts the video with captions ready to post.

The language model and the voice both run on my own computer, so a video costs nothing to make and works with the internet off.

The hard part was not generating things, it was stopping the character from changing appearance between scenes. One file now describes the character, and every prompt repeats it word for word.

2026 · Python, scikit-learn

Stock-ranking research engine

The project that failed first, and what I did about it.

Version one tried to predict whether a stock would rise tomorrow. It looked strong in testing, then lost 5.5% on a slice of data I had locked away — while simply buying and holding made 18.6%.

So I wrote down why it failed and rebuilt it to answer a different question: which stocks beat the market average over five days. 128 stocks, 374,365 rows of daily prices, 2,328 versions tested.

This time the edge held up on the locked-away data. It is still not worth trading, because the profit is thinner than the cost of trading — and reporting that is the whole point.

2,328 configurations38 leak checksbeat 40 of 40 random controls

Both models scored higher on data they had never seen than in testing. That is the opposite of what a model that is fooling itself does.

Desktop agent tooling

Five small servers that let an AI assistant use my computer.

Ask in plain English and it opens the right app, adds a task to my planner, or searches my notes — about thirty separate tools across five servers.

An assistant can be talked into things by whatever text it reads, so I built the limits first: it can only launch apps from a list I approved, it refuses banking and password windows outright, it stops at sixty actions a minute, and it writes down everything it does. A single file on disk kills all input instantly.

2026 · Windows, networking

Two machines, two hours apart

My home laptop, reachable from campus, without opening a single port.

The machine at home sleeps until it wakes itself on a schedule. From campus I can take over its screen, run a command on it, or drop a file in a folder and watch it appear on the other side. The two are joined by a private encrypted network, so nothing is exposed to the open internet and no company holds my files.

Almost none of this worked the first time, and none of the failures printed an error. The machine simply did not wake up, and there was nothing to read.

Waking it took five fixes stacked on top of each other, and four of them were symptoms. The real cause was a second sleep timeout Windows does not show in its settings screens at all — you can only see it by asking the power tool to dump hidden values. It applies specifically when the computer wakes for a scheduled task, and it was putting the machine back to sleep about two minutes after every successful wake. Along the way I also found that the sleep command most of the internet recommends silently turns wake-ups off, because of how its arguments land on the real function underneath.

The lesson I actually keep: when a system fails silently, stop trusting what it displays. My file sync looked perfectly healthy in its own window for ten days while it copied nothing, after an update quietly left it running under a blank identity. Now I check that a real file moved, not that the screen looks fine.

Business model explainer

A tool that shows you exactly how a business makes money.

Pick a company and watch one customer dollar move: who pays whom, what the product actually costs, and where the margin is hiding. Change one number and the whole picture moves with it.

8-bit CPU from discrete chips

A processor built out of individual logic chips, not bought as one.

A clock, two registers, an adder, sixteen bytes of memory and a display, wired together on a breadboard and driven by a shared bus — then moved onto a printed board once it runs.

I have done the reading: the datapath, the instruction set, and the parts list. Nothing is wired yet, and I am not going to pretend otherwise. It is the project I most want a workbench and other people's advice for.

Selling

Booking sites for local shops

Barbers, salons and restaurants lose appointments to the phone.

The demo on the right is a working app, not a picture of one: real accounts with email verification, a reservation system with live table availability, and an account page where a guest can cancel a booking.

I wrote the attack tests too — for stolen sessions, injected database commands, and cancelling someone else’s reservation. Thirteen of them run on every change and all thirteen pass. One real bug turned up during the build: password-reset links were being built from a header an attacker controls.

The hard part is not the code. I can build the site in a weekend; I have never walked into a barbershop and asked for the sale. That is the part I am trying to get better at.

Crucible, a demo steakhouse — no paying client yet. Node and Express, sign-up through booking, on a phone and a laptop.

How I work

Finish, then use it daily

Six of these run on my machine every day. Real use finds bugs no review does — one stale lock file quietly stopped seven of my apps from opening, with no error at all.

Report the result, not the story

My first trading model lost money on data it had not seen. Writing that down is what made the second one work. A negative result you can trust beats a positive one you cannot.

Build the limits first

Anything that can control a computer gets a kill switch, an allowed list, and a log before it gets features. Safety added afterwards is just a wish.
